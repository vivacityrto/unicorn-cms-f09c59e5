# Audit: 2026-08-18 — legacy invite_user RPC dropped

**Trigger:** drift-surfaced — parked cleanup item noted in the invitation role-ceiling audit (`docs/audit-log/entries/2026-08-18-invitation-role-ceiling-service-role-bypass.md`).
**Scope:** the single SQL function `public.invite_user(uuid, text, text)`. Did not touch the edge function `invite-user` (a different, actively-used thing with a confusingly similar name) or any RLS policy.

## Findings

- `public.invite_user(p_tenant_id uuid, p_email text, p_role text)` inserted into `public.user_invitations` using columns `role` and `token`. The live table has `unicorn_role` and `token_hash` instead — this schema shape predates the current one and was never migrated forward. Every real invocation would raise a Postgres "column does not exist" error.
- It also read/wrote `public.tenant_members` with `p_tenant_id uuid` typed as `uuid`, but `tenant_members.tenant_id` (like `tenants.id`) is `bigint` in the current schema — a second, independent mismatch.
- Grepped `src/` and `supabase/functions/**` for any caller (`rpc('invite_user'`, `.rpc("invite_user"`): none found. The only hit anywhere in the repo was the autogenerated `src/integrations/supabase/types.ts` type stub, not a call site.
- Despite being dead, it remained `EXECUTE`-granted to `authenticated` (in addition to `service_role`/`postgres`), meaning any signed-in user could invoke `supabase.rpc('invite_user', {...})` directly and hit this broken path. Not a live vulnerability (it errors before completing any mutation), but needless reachable surface referencing a stale, incorrect schema shape.

## Fix

Dropped the function outright (`DROP FUNCTION IF EXISTS public.invite_user(uuid, text, text)`) rather than fixing its column references — it has no callers to preserve, and the live path (`invite-user` edge function, wired through `invite_user`'s actual working replacement) already exists and is what all current UI flows use.

## Code changes

- Migration `20260818050000_drop_legacy_invite_user_rpc` (applied directly to production via Supabase MCP; committed to `supabase/migrations/` in this PR).
- No edge function or frontend changes — confirmed zero callers before dropping.

## Decisions

- No replacement needed; the actively-used `invite-user` edge function (see `docs/audit-log/entries/2026-08-18-invitation-role-ceiling-service-role-bypass.md` for its write path into `user_invitations`) already covers this need correctly.
