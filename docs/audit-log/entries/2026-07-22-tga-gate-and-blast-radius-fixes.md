# Audit: 2026-07-22 — tga-gate-and-blast-radius-fixes

**Trigger:** drift-surfaced
**Scope:** Follow-up to [[2026-07-22-restore-invite-validation-anon-grant]] — fixed the remaining confirmed/likely-broken findings from that session's blast-radius sweep of the 12–21 Jul security remediation: the TGA sync gate cluster, three `users.select('*')` hard-fail sites, and the `internal-onboarding` storage bucket policy asymmetry. Did not action: the broader git-drift reconciliation for the rest of the ~46 untracked July migrations, or the process/checklist recommendation to prevent recurrence (both explicitly parked again).

## Findings
- **TGA sync gate cluster, fixed.** `tga_swap_scope_from_staging`, `tga_start_staged_sync`, `upsert_excel_template_bindings`, and `stall_bulk_document_job` all carried the same unconditional `IF NOT is_vivacity_team_safe(auth.uid())` gate from `l3_gate_tga_sync_cluster`, rejecting every service-role edge-function call unconditionally. Fixed all four with the passthrough pattern already proven safe in production on `add_package_to_tenant` (`IF (SELECT auth.uid()) IS NOT NULL AND NOT is_vivacity_team_safe((SELECT auth.uid()))`). A fifth function, `persist_tga_scope_items`, had no confirmed live caller (dormant, same cluster) but got the identical fix for defense-in-depth, applied as a separate follow-up migration.
- **Secondary bug found and fixed in the same pass:** `tga_start_staged_sync` contained `p_triggered_by := auth.uid();` immediately after the gate, unconditionally overwriting a caller id that the calling edge function (`tga-sync/index.ts`) had already verified via a real `auth.getUser(token)` check and passed in explicitly — silently discarding correct attribution and replacing it with `NULL` for every service-role call. Removed; this line was masked from ever executing by the gate itself, so it's been dormant since the gate first landed.
- **Verified end-to-end against the originally-reporting client** (tenant 7520, "Start Training Group", RTO 22381): triggered a real "Sync Now"; `tga_rest_sync_jobs` shows `status='done'`, `last_error=null` (prior two attempts both showed the exact `Forbidden: staff only` error); `tenant_rto_scope` gained 98 real rows across 5 scope types for that tenant.
- **`users.select('*')` hard-fails — two real, one phantom.** `TenantDetail.tsx` and `TenantMembers.tsx` confirmed genuinely broken (M5 personal-contact column REVOKE turning a wildcard select into a hard query error) and fixed with explicit column lists, verified directly against `origin/main`. The third originally-reported site, `ManagePackages.tsx`, turned out not to exist — deleted 14 Jul 2026 (co-authored `angela-connell`), over a week before this whole investigation started and unrelated to the security remediation. Root cause of the false finding: this session's local `unicorn-cms-f09c59e5` checkout was stale (hadn't been pulled since before that deletion), feeding a phantom site into the original blast-radius sweep. Re-synced the local working tree mid-session (with explicit user approval, after an unapproved `git pull` was flagged and corrected) to prevent this recurring for the rest of the session.
- **`internal-onboarding` bucket asymmetry — investigated, found unreachable in practice, tightened anyway.** The `INSERT` policy (`is_vivacity_team_safe`) vs. `SELECT`/`UPDATE`/`DELETE` policies (`check_permission(..., 'admin.team_users.manage', 'full')`) really is asymmetric at the RLS-definition level, exactly as originally flagged. But the only real caller — the `staff-onboarding-workbook` edge function, used by `WorkbookUploader.tsx`/`OnboardingHub.tsx` — uses a service-role client that bypasses these RLS policies entirely, and enforces its own single, uniform `admin.team_users.manage:full` check for upload/signed-url/remove alike before branching into any action; the route itself is additionally gated `requireSuperAdmin`. No live user has ever been able to hit "upload succeeds, then can't read it back." Tightened the `INSERT` policy to match its siblings anyway as zero-risk hygiene, not as a bug fix.
