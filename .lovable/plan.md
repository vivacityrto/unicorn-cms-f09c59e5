## Plan: Add RLS SELECT policy for global governance documents

### Problem
The `ClientGovernanceDocumentsPage` in the client portal needs to read governance document metadata (title, category, framework, description) from the `documents` table. Governance documents are master templates with `tenant_id = null`. Existing SELECT policies on `documents` evaluate `tenant_id` against the current user's tenant, so client portal users (who are not SuperAdmins/Team Leaders) fail the policy when querying rows where `tenant_id IS NULL`.

### Change
A single additive migration that creates one new RLS policy on `public.documents`.

### Migration SQL
```sql
CREATE POLICY "documents_select_global_for_tenant_users"
  ON public.documents
  FOR SELECT
  TO authenticated
  USING (
    tenant_id IS NULL
    AND EXISTS (
      SELECT 1 FROM public.tenant_users tu
      WHERE tu.user_id = auth.uid()
    )
  );
```

### Policy behaviour
- Applies only to `authenticated` role.
- Allows SELECT on rows where `tenant_id IS NULL` (global/master documents).
- Requires the calling user to have at least one row in `public.tenant_users`, confirming they are associated with a tenant.
- Does not grant access to tenant-scoped documents (`tenant_id IS NOT NULL`).
- Does not modify, drop, or replace any existing policies, tables, columns, indexes, triggers, or functions.

### Rollback
```sql
DROP POLICY "documents_select_global_for_tenant_users" ON public.documents;
```

### Files touched
- A new migration file in `supabase/migrations/` (generated by the migration tool).

### Verification
After migration, an authenticated client portal user with a `tenant_users` association should be able to run:
```sql
SELECT id, title, category, framework_type, description FROM public.documents WHERE tenant_id IS NULL;
```
without receiving an RLS denial.
