## Seeding (`beforeAll`, 60s timeout)

- `RUN_ID = vitest-<base36-ts>-<rand6>` namespacing every seeded row.
- Insert two `tenants` (autogenerated bigint `id` captured): `name`, `slug=test-tenant-{a|b}-<run>`, `status='active'`.
- Personas A1, A2, B1, S via `auth.admin.createUser({ email_confirm: true })`, then `users` upsert on `user_uuid` (handles `link_auth_user_to_profile` stub-row collision), then `signInWithPassword` on a fresh anon `createClient` (per-persona, `persistSession:false`).
- `tenant_members`: A1/A2 → Tenant A, B1 → Tenant B, all `role:'member'`, `status:'active'`. **No row for S** (staff identity comes from `unicorn_role`).
- Conversations via service role: `convA`, `convA2`, `convA_noStaff`, `convB` on `tenant_conversations`.
- Participants per spec — critically `convA_noStaff` has only A1 (NO staff), so tests 11–13 genuinely prove `tm_select_staff` bypasses participant matching.
- One seed `tenant_messages` row per conversation.

## Cleanup (`afterAll`, 60s, try/catch warn)

Reverse cascade: `tenant_messages` → `conversation_participants` → `tenant_conversations` → `audit_events` (entity='tenant_message', user_id IN personas) → `tenant_members` → `users` → `tenants` → `auth.admin.deleteUser` per persona.

## Risk assessment

- **Bundle safety**: non-`VITE_` name + read via `process.env` (never `import.meta.env`) + warning header → key cannot leak to browser bundle.
- **CI safety**: `describe.sequential.skipIf` makes runs without the secret a clean skip.
- **Data safety**: every row namespaced via `RUN_ID`; cleanup is best-effort with `console.warn` (does not mask test failures).
- **Schema safety**: zero migrations, zero RLS / FK / policy modifications. Pure read/write against existing tables.
- **No production impact**: file scope = `src/test/`, never imported by app code.
- **Backward-compat**: original 13 placeholder tests preserved exactly; their `vi.mock` only affects the legacy block — the live block uses fresh `createClient` instances and never imports the app's supabase singleton.
